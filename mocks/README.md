# Пробники по физике INVARIANT

| Экзамен | Открытый | По коду | Заданий | Время | Первичные баллы |
|---|---|---|---:|---:|---:|
| ОГЭ | Вариант 1 | Вариант 2 | 22 | 180 мин | 39, из них 23 автоматически |
| ЕГЭ | Вариант 1 | Вариант 2 | 26 | 235 мин | 45, из них 28 автоматически |

Каталог открывается по `mocks.html?exam=oge` и `mocks.html?exam=ege`. Прямая ссылка дополнительно фиксирует `variant` и `v`, например `mocks.html?exam=ege&variant=ege-02&v=1`. Ссылки работают под префиксом `/zadachnik-oge/`.

Варианты авторские. Число и позиции заданий, лимиты времени, краткие форматы и распределение баллов сверены со спецификациями и демоверсиями ФИПИ 2027. У каждого задания есть номер, тема, навык, тип, баллы и эталон. Развёрнутые задачи дополнены критериями по шкале задания. Для №17 ОГЭ описано оборудование и даны готовые измерения для обработки. Официальная процедура предусматривает самостоятельное измерение. Состав в первой версии не зависит от готовности банка агента 2. Идентификаторы карточек открытого банка в этих вариантах отсутствуют.

Архивы ФИПИ с PDF [ОГЭ](https://doc.fipi.ru/oge/demoversii-specifikacii-kodifikatory/2027/fi_9_2027.zip) и [ЕГЭ](https://doc.fipi.ru/ege/demoversii-specifikacii-kodifikatory/2027/fi_11_2027.zip).

## Как проходит работа

1. Ученик открывает вариант, читает правила и начинает попытку. Черновик хранится в браузере отдельно для экзамена, варианта, версии и каждой попытки. Таймер использует сохранённое время окончания. По истечении времени черновик автоматически переходит в сданную работу, в том числе при повторном открытии. Для закрытой версии после обновления нужен прежний код.
2. После сдачи видны ответы, баллы за краткие задания и темы для повторения. Ученик скачивает JSON работы и вручную передаёт его репетитору. Файл содержит ID попытки, вариант и версию, время сдачи и ответы без имени, кода доступа и ключей.
3. Репетитор входит в кабинет, открывает «Пробники и коды» и загружает работу. Кабинет заново проверяет краткие ответы и показывает развёрнутые условия, эталоны и критерии. Репетитор ставит балл за каждое развёрнутое задание, при необходимости пишет комментарии и скачивает разбор. Ученик импортирует файл на экране той же попытки. После этого появляется итоговый первичный балл. Пакеты `invariant-mock-submission` и `invariant-mock-review` версии 1 используют отдельный вход импорта. Прежний обмен ДЗ через `RES-` продолжает работать в своём разделе кабинета.

## Упаковка и выпуск новой версии

Запечатанные данные публикуются в `mocks/data/*.enc.json`. Контейнер версии 1 использует AES-128-GCM. Код `IM1-…` содержит 16 случайных байт в base64url. Контейнер содержит IV из 12 случайных байт и шифротекст с 128-битным тегом. IV и шифротекст закодированы в base64url. Строка AAD `invariant-mock:1:<exam>/<id>/<version>` связывает контейнер с карточкой.

Мастер-данные `author.mjs`, список `variants.mjs`, реестр `registry.json` и список выдачи `issuance.json` хранятся в соседнем закрытом каталоге `../invariant-mocks-private/`. Держите резервную копию реестра вне каталога Pages. Для локальной сборки:

```sh
node mocks/tools/pack.mjs ../invariant-mocks-private
node mocks/tools/verify.mjs
```

Упаковщик сверяет все номера и баллы, проверяет обратной расшифровкой состав каждого контейнера и сохраняет коды ранее выпущенных версий. Для исправления содержания, изменения доступа или смены кода добавьте следующую версию в `variants.mjs`. Старую версию пометьте `archived: true`. Она исчезнет с витрины, но её прямая ссылка, прежние попытки и выдача сохранятся. Действующий код можно передать другому человеку. Разблокированный браузер получает состав и эталоны, необходимые для самопроверки.

## Стык с кабинетом

Владелец кабинета добавляет `<div data-mock-tools></div>` в защищённый исходник `teach.html`, например перед `<main id="teacher-view">`. Из корня объединённого checkout:

```sh
node mocks/tools/teacher-entry.mjs ../invariant-lessons-private ../invariant-mocks-private/issuance.json
```

В защищённой упаковке кабинета добавить файл `'mocks-entry.js'` после `'teach.js'` в массив `scripts` пакета `teacher-workspace.enc.json`. Упаковка включает его как встроенный скрипт из приватного источника. Затем пересобрать кабинет обычной командой `node scripts/protect-teacher.mjs ../invariant-lessons-private --workspace-only`, передав действующий пароль журнала через stdin.

Модуль вызывает `mountTeacherMocks(anchor, issuance)` из `mocks/teacher.mjs`. `anchor` — элемент `[data-mock-tools]`, `issuance` — объект, отображающий `<exam>/<id>/<version>` в код. Публичные карточки загружаются функцией `getCatalog()` из `mocks/config.mjs`. Модуль читает код из защищённого пакета после входа. В отправляемой ссылке находятся экзамен, ID и версия.

Репетитор открывает «Пробники и коды» → «Выдать вариант», выбирает экзамен и версию в списке и нажимает «Скопировать сообщение». При запрете Clipboard браузер выделяет сообщение для копирования вручную. Ссылка для ученика отправляется вместе с кодом отдельной строкой.

## Приёмка на объединённой сборке

```sh
INVARIANT_MOCKS_INTEGRATION=../invariant-integration \
INVARIANT_CABINET_SOURCE=../invariant-lessons-private \
node mocks/tools/verify.mjs --browser
```

Требуются `playwright-core` и Chrome. Указать путь к Chrome можно через `OGE_CHROME`. Тест поднимает временную сборку под `/zadachnik-oge/`, собирает реальный формат кабинета с тестовым паролем и временными кодами, а затем открывает независимые профили учителя и ученика. Для проверки одного модуля параметры интеграции можно убрать. Настоящие коды используются локально для проверки контейнеров и сканирования публикуемого дерева. Вывод тестов их не содержит.

В общей сборке владелец главной и уроков подключает ссылки на `mocks.html?exam=oge` и `mocks.html?exam=ege`. Перед публикацией прогнать вход в пересобранный кабинет с действующим паролем, выдачу рабочего кода и переходы с главной и курсов. Рабочий пароль в ветку пробников не передаётся.
