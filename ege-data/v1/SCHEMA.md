# Банк ЕГЭ по физике, версия 1

## Подключение

- Каталог и словарь тем доступны по пути `ege-data/v1/catalog.json`. Код страницы приводится под префиксом GitHub Pages, например `/zadachnik-oge/ege-bank.html?topic=dc-circuits`.
- `practice-catalog.json` содержит `{ tasks: [...] }` с записями `ready` из справочного каталога. Импортёр создаёт этот файл для первой загрузки учебного задачника.
- Учебная навигация строится по порядку из `bank/ege/practice-modules.mjs`. Модуль объединяет тематические блоки одного раздела, а карточка входит в основной блок по своему `topic`. Ссылки на уроки, дополнительные темы и оригиналы сохраняют прежние идентификаторы.
- Постоянная ссылка на карточку строится как `ege-bank.html?task=ege-fipi-4EAC46`. Идентификатор формируется из официального кода в верхнем регистре. Поле `sourceCode` сохраняет написание ФИПИ. Пример задачи со ссылочным условием — `ege-fipi-474F4B`.
- Для уроков и пробников используйте [готовые ID по темам](ready-by-topic.json). Значение каждого ключа темы — массив объектов `{id, keyStatus}`. Подборка родительской темы включает потомков. Для работы с полным текстом нужен `status === "ready"`. Для автопроверки также требуется проверенный ключ и поддержка указанного правила.
- Для вариантов в формате ЕГЭ-2027 учитывайте `applicability`. `legacy-format` обозначает один ответ из списка, отсутствующий в спецификации 2027. `unverified-year` означает, что год и позиция в варианте не установлены. Подбор полного пробника требует редакторской сверки с планом КИМ.

`catalog.json` содержит `schemaVersion: 1`, `topics[]` с `slug, title, parent` и `tasks[]` с `id, sourceCode, topicSlugs, cardPath, status`. `parent: null` отмечает корневую тему. `cardPath` и пути вложений разрешаются от каталога сайта, включая префикс Pages. У задачи возможны несколько тем и принадлежность нескольким разделам.

| Статус | Что есть в INVARIANT |
|---|---|
| `ready` | Полное условие с нужными материалами. Возможна ручная проверка |
| `partial` | Часть условия с указанной причиной и ссылкой на оригинал |
| `reference` | Код, метаданные, причина и ссылка на ФИПИ. `cardPath: null` |

Поля для выдачи включают `title, hasFigure, answerType, keyStatus, sourceUrl, reason, applicability`. `kes` содержит исходные коды КЭС. `sourceDigest` служит для отслеживания изменений оригинала. `sourceChange` принимает `changed`, `missing` или `restored`. Для исчезнувшего номера сохраняется постоянная ссылка и описание статуса.

## Условия и ключи

JSON по `cardPath` содержит `id, sourceCode, sourceUrl, topicSlugs, parts, answerType, keyStatus`. Тип ответа принимает `short`, `single`, `multiple`, `matching`, `extended` или `unknown`. Метка ФИПИ «Краткий ответ» включает некоторые задания на последовательности и два числа. При автопроверке используйте `key.rule`.

Выводите `parts` последовательно. Для безопасного отображения используйте [рендерер](../../ege-bank/render.js).

| Элемент | Поля |
|---|---|
| `prompt` | `children`, блок условия |
| `text` | `text`, обычный текст |
| `element` | `tag, attrs?, children`, ограниченный набор тегов для абзацев, индексов, списков и таблиц. `grid: "1"` включает сетку таблицы |
| `math` | `tag, attrs?, children`, элементы MathML |
| `image` | `path, sourceUrl, alt, credit?`, вложение в своей позиции в условии или варианте. У авторской схемы ссылка указывает на исходное задание |
| `options` | `items`, массив вариантов. Каждый вариант — массив элементов. Нумерация начинается с 1 |

`keyStatus` принимает `missing`, `author-verified` или `official-verified`. При подтверждённом ключе `key` содержит `accepted[]` (строки), `rule` и `credit`. `number` проверяет равенство чисел, `measurement-pair` — два числа в заданном порядке, `ordered-digits` — порядок цифр, `unordered-digits` — набор цифр с учётом повторов. Разделитель десятичных дробей может быть запятой или точкой. `solution` при наличии содержит `credit, parts`. Автопроверка доступна при наличии ключа. В развёрнутых заданиях поле числового итога появляется, когда задан проверенный итог. Разбор и критерии выводятся отдельно.

## Воспроизведение

Нужен Python 3.10+ и `curl`. Установите зависимость в отдельное окружение и укажите внешний каталог кэша. Повтор того же снимка использует этот кэш. Для обновления используйте новый каталог с новой датой. Успешные ответы сохраняются по одному. При временной сетевой ошибке клиент ждёт и повторяет запрос. При 401, 403 или 429 прекращает обход. Если запуск прерван, повторите команду с тем же кэшем. При неполном инвентаре или расхождении контрольных счётчиков запись каталога отменяется.

```sh
python3 -m pip install -r ege-bank/import/requirements.txt
python3 -B ege-bank/import/import_bank.py --cache /path/to/snapshot-2026-11-24 --date 2026-11-24
python3 -B ege-bank/import/import_bank.py --cache /path/to/snapshot-2026-11-24 --date 2026-11-24 --check
python3 -B ege-bank/tests/verify_import.py
python3 ege-bank/tests/verify_bank.py
node ege-bank/tests/verify_practice.mjs
node scripts/verify-study-flows.cjs
```

Для браузерного теста нужен `playwright-core` и установленный браузер, путь задаётся в `OGE_CHROME`. Тест поднимает локальный HTTP-сервер с префиксом Pages. `--check` только читает кэш и готовый набор данных и сравнивает их побайтно. `--offline` пересобирает набор без сети. `--sample --output /path/to/local-site` создаёт эталонную выборку оригиналов. `--local-full --output /path/to/local-site` собирает оригинальные условия и изображения для локальной сверки. Для просмотра такого снимка используйте локальную копию сайта и замените в ней файлы `ege-data/v1/` данными снимка, сохранив `verified-keys.json`. Затем запустите локальный HTTP-сервер. Обе команды с оригиналами принимают внешний каталог сайта.

[Сводка снимка](import-report.json) содержит контрольные счётчики, список неполных записей и очередь сверки тем. [Протокол сверки](AUDIT.md) описывает источник, выборку и найденные ограничения.
